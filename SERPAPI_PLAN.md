# SerpApi migration plan (flights + hotels)

Replace the Duffel flight search and the Mapbox/mock hotels with SerpApi `google_flights` and `google_hotels`. Real data or a search link, never invented offers. Work on `dev`. `[VERIFY]` = still-open assumption; `[CONFIRMED]` = settled by step 1's capture (RUH→CDG, 2026-11-25/30, Paris hotels) or by hand.

## Decisions

1. **Currency/locale:** `SERPAPI_LOCALE = {"currency": "SAR", "gl": "sa", "hl": "en"}`, a constant in `services/serpapi.py` (not env). [CONFIRMED] flight `price` comes back as a plain SAR number (e.g. `531`); hotel rates are SAR strings (`"SAR 4,095"`, non-breaking space).
2. **Airports:** `geocoding.search_airports()` becomes **Duffel only** (`places/suggestions`); delete the Mapbox airport fallback. [CONFIRMED] Mapbox Search Box airport results carry no IATA field (`metadata` has phone/website/hours, `external_ids` only `dataplor`, names like "Riyadh International Airport" have no code). Duffel results always have `iata_code`. The resolver (§3) also resolves the destination airport; the result is saved on the trip and shown in the flights panel with a Change control. Delete `flights._resolve_place_code`. Mapbox config stays (city search `search_places`, itinerary geocoding).
3. **Caps:** per-user 30 searches/month (admins via `users.is_admin` exempt from this cap only). Global `SERPAPI_MONTHLY_CAP=210` (250 minus a 40 reserve) until demo day, then 240. Hourly cap 45 (SerpApi's limit is 50).
4. **Hotel button:** the hotel's `link` if present (may be `http://`), else `googleMapsSearchUrl(name, city)`. Never build Booking.com URLs; delete the existing Booking.com helpers.
5. **Stale results:** "Prices as of <date>" + Refresh, no automatic re-search. **Booking** is a form POST, not a link (§4/§5); `post_data` is never cached, logged, or stored.

## 1. Search budget (free plan: 250/month, 50/hour; our cap 210 until demo day)

| User action | SerpApi searches | Notes |
|---|---|---|
| Open trip page / reopen trip | 0 | Page load uses `cached_only=true`; panels collapsed by default |
| Open Flights panel, round trip (first time) | 1 | `type=1`; outbound offers carry `departure_token` [CONFIRMED] |
| Switch to one way (first time) | 1 | `type=2`; offers carry `booking_token` directly [CONFIRMED] |
| Pick an outbound flight | 1 per distinct outbound | `departure_token` search returns the return list [CONFIRMED] |
| Click "Book" | 1 per click | `booking_token` search; never cached because `post_data` is short-lived |
| Change origin/destination airport | 1 on the next panel view | New airport pair = new cache key |
| Open Hotels panel (first time) | 1 | One `google_hotels` search |
| Nonstop toggle, re-picking the same outbound, reopening | 0 | Served from the DB cache |

A typical full trip (round trip + pick + Book + hotels) costs **4**, so 210 covers **~52 trips/month**. Every Book click costs 1, so repeated clicks are covered by the burst limit (§3). Airport resolution uses Duffel/LLM, never SerpApi. Dev and tests cost 0 (mock mode). SerpApi may serve identical searches from its 1h cache for free; the budget assumes every call is charged. `account.json` is free [CONFIRMED: usage moved only with searches].

## 2. Data model (new tables via `Base.metadata.create_all`; new columns via `_SCHEMA_COLUMNS` in `main.py`)

- `serpapi_cache`: `id`, `trip_plan_id` FK→trip_plans ON DELETE CASCADE, `kind` VARCHAR(20) (`flights_round`, `flights_one_way`, `flights_return`, `hotels`), `cache_key` CHAR(64), `payload` JSON (our *normalized* data incl. tokens, never the raw response), `created_at`, `expires_at`. UNIQUE(`trip_plan_id`, `kind`, `cache_key`). No `booking` kind.
- **Cache key** = sha256 of `origin_airport|destination_airport|start_date|end_date|adults|children|trip_type` (hotels use `destination` instead of the airports). `flights_return` appends the parent offer id. **TTL** = `SERPAPI_CACHE_TTL_HOURS` (default 24). An expired row is still served with `stale=true`; it is re-searched only via an explicit Refresh (`refresh=true` accepted only when stale).
- `serpapi_usage` (quota log): `id`, `user_id` FK ON DELETE SET NULL, `engine` VARCHAR(20), `created_at` (indexed). Monthly, hourly, and per-user counts are `COUNT(*)` queries.
- `trip_plans` columns: `selected_hotel` VARCHAR(255), `origin_airport` VARCHAR(3), `destination_airport` VARCHAR(3), all NULL, exposed on `TripPlanPublic`. Resolved once, reused until cleared (§3 "Trip input changes").

## 3. Backend design

**Airport resolver (`services/flights.py`):** `_resolve_airport(label) -> str | None`: (1) the `(XXX)` already in the label (`_extract_iata_from_label`); (2) else `search_airports(city part)`, first result whose `city` matches via `city_comparable_key`; (3) else one `complete_chat` call ("main airport IATA code for <city>"), accepted only if it matches `^[A-Z]{3}$` **and** `search_airports(code)` returns it; (4) else `unavailable_reason="no_airport"` + search link. Written to `trip.origin_airport` / `trip.destination_airport`. Without Duffel configured, `search_airports` returns nothing and the resolver ends in `no_airport` unless the label has a code.

**Trip input changes (step 6):** `reset_trip_travel_cache(db, trip)` in `services/serpapi.py` NULLs both airport columns and deletes the trip's `serpapi_cache` rows; if the destination changed it also clears `selected_hotel`. `quiz.submit_quiz_answers` snapshots `(origin, destination, start_date, end_date)` before applying answers and calls it once if anything differs (covers every path through `_apply_answer_to_trip`, incl. the `include_flights` origin clearing). `destinations.select_destination` calls it when the destination changes. Travelers changes need no reset (they're in the key).

**`services/serpapi.py` (new, the only file that knows the key):**
- `serpapi_search(db, user, params) -> dict` merges `SERPAPI_LOCALE`. Mock mode: return the matching fixture, no usage row, no network. Otherwise: no key → `SerpApiUnavailable("not_configured")`; take `pg_advisory_xact_lock`, check monthly, hourly, and per-user caps (per-user skipped for admins); insert the usage row, commit, call `https://serpapi.com/search.json` (urllib). On network errors, HTTP 401/429/5xx, or a JSON `error` other than "no results" [VERIFY wording], delete the usage row (not charged [VERIFY]) and raise `SerpApiUnavailable("error")`.
- `get_cached(db, trip_id, kind, key) -> (payload, stale) | None` and `put_cached(...)` (upsert).
- Mock fixtures: `booking_token` + `type=1` → `booking.json`, `booking_token` + `type=2` → `booking_one_way.json`, `departure_token` → `flights_return.json`, `type=2` → `flights_one_way.json`, `type=1` → `flights_round.json`, `google_hotels` → `hotels.json`.

**`services/flights.py` (rewrite; delete `_mock_offers`, `_search_duffel`, `_offer_from_duffel`, `_segment_from_duffel_slice`, `_resolve_place_code`; keep `search_airport_suggestions`, `_duffel_request`, `duffel_configured`, `_google_flights_url`, `_format_duration`):**
- Base params: `engine=google_flights, departure_id, arrival_id, outbound_date, return_date (type=1 only), type, adults, children` + locale [CONFIRMED names, except `children` untested]. No `start_date` → `no_dates`; no `end_date > start_date` → one way only.
- **Follow-up calls send the full base params of the original search plus the token** [CONFIRMED: a token-only call fails with "Missing `departure_id` parameter"]. Returns: round base + `departure_token`. Booking: the base of the offer's trip type (`type=1` + `return_date`, or `type=2`) + `booking_token`, never both tokens.
- `search_flights(db, user, trip_id, trip_type, cached_only, refresh) -> FlightsResponse` (outbound or one-way list). `search_returns(db, user, trip_id, offer_id) -> FlightsResponse`; `departure_token` from this trip's cached outbound row under the current key. `booking_options(db, user, trip_id, offer_id) -> BookingResponse`; `booking_token` from this trip's one-way or return rows under the current key. Always a live search; the response is returned, not stored.

**Endpoints (`routers/trips.py`; all via `get_owned_trip`):** `GET /trips/{id}/flights?trip_type=round|one_way&cached_only&refresh` (changed; includes resolved airports), `POST /trips/{id}/flights/{offer_id}/returns`, `POST /trips/{id}/flights/{offer_id}/booking`, `PUT /trips/{id}/airports` `{origin?, destination?}` (code from the picked label, confirmed by `search_airports`, else 400), `GET /trips/{id}/hotels?cached_only&refresh` (changed), `PUT /trips/{id}/selected-hotel` `{name | null}` (must match a name in this trip's hotels cache, else 400), `GET /health/serpapi` `{configured, mock}`. Keep `/health/duffel`. Search endpoints also call `enforce_rate_limit(..., key=f"user:{id}", max_calls=10, window_seconds=60)`.

**Fallback:** failures are `200` with `source="unavailable"`, `unavailable_reason` ∈ {`not_configured`, `quota`, `user_limit`, `error`, `no_airport`, `no_dates`, `no_results`, `not_loaded`}, an empty list, and `search_url`. Search URLs: `_google_flights_url` (IATA or city + dates + adults; drop the `airline` arg); hotels `https://www.google.com/travel/search?q=hotels+in+<city>` + dates [VERIFY date params]. After a successful search use `search_metadata.google_flights_url` / `google_hotels_url` instead [CONFIRMED present].

## 6. Security and abuse

- `SERPAPI_API_KEY` only in `.env` / Render (`sync: false`) and only inside `serpapi_search`. It goes in the query string [VERIFY header support], so the full URL is never logged, put in exceptions, or returned; logs carry engine + HTTP status + SerpApi's `error` text with the key replaced by `***`. Raw `search_metadata` is never returned except the two google.com URLs. Tokens stay server-side; the client sends only `offer_id`, which must exist in this owner's trip cache. `post_data` reaches the client (the browser must submit it) but is never persisted or logged.
- Quota: per-user 30/month (admins exempt), burst limit (`rate_limit.py`, in-process, fine on one Render worker), global hourly 45 + monthly 210, `cached_only` page loads, Refresh only when stale. Reserve-then-call under an advisory lock means concurrent requests can't overshoot. `SERPAPI_MOCK` defaults to false and is `"false"` in `render.yaml`.
